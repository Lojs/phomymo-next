WHAT THIS PROJECT IS
A browser-only label designer for Phomemo thermal printers. React 19 +
TypeScript + Vite, no backend, no accounts, no server-side state. The raster is
generated in the browser and never leaves the device. Printing is over Web
Bluetooth or WebUSB. It ships as a self-hosted Docker container (nginx + HTTPS,
because printing requires a secure context).

ONE OF YOUR CLAIMS DID NOT HOLD - PLEASE JUDGE THIS
You wrote that the service worker cached /icons "immutable" although those files
are not content-hashed. In this deployment I believe it does not: nginx serves
/icons/ with Cache-Control: no-cache, and the worker routes icon requests
through isIcon(), which revalidates them network-first. I therefore changed
nothing. If you can still see a path where that is wrong, say so.

ALSO ESTABLISHED ON THE USER'S MACHINE - PLATFORM FACTS, NO NEED TO RE-CHECK
USB printing cannot work on Windows, for any browser. Windows binds the device
to a kernel-mode print driver, which is why Device Manager shows it as "USB
Printing Support"; WebUSB needs the device free of that binding, which requires
a manual WinUSB driver override. The symptoms were a "Permission denied" toast,
Transfer Errors in usb-internals, and window.isSecureContext === true. Bluetooth
works on Windows; USB works on Linux and the Raspberry Pi.

KNOWN DEBT, DELIBERATE - TELL ME IF YOU DISAGREE WITH THE REASONING
The five BLETransport handles (device, server, service, writeChar, notifyChar)
remain `any`. I installed the real types and attempted the change; it produced
about twenty errors, mostly genuine `possibly null` plus out-of-spec properties
the transport attaches to the device itself (_hasDisconnectHandler). The only
route through was non-null assertions, which would silence the compiler without
making the printer path safer. I left it and documented why. Do you agree, or do
you see a way to do it that is actually safe?
